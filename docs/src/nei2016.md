# 2016 US EPA National Emissions Inventory (NEI) data

We have a data loader for CMAQ-formatted monthly US National Emissions Inventory data for year 2016,[`NEI2016MonthlyEmis`](@ref).

## Download Configuration

Because there is an issue with the EPA's FTP server that we download the data from you may need to set the following environment variable before using it:

In Julia:

```julia
ENV["JULIA_NO_VERIFY_HOSTS"] = "gaftp.epa.gov"
```

or in a bash shell:

```bash
export JULIA_NO_VERIFY_HOSTS=gaftp.epa.gov
```

## Sectors and vertical allocation

The sector name is the middle part of the EPA file name `2016fh_16j_<sector>_12US1_month_MM.ncf`.
The merged surface file `mrggrid_withbeis_withrwc` contains every surface sector (including BEIS
biogenic and residential wood combustion) but none of the "inline" elevated point sectors.
Those are available as separate files on the same grid and can be added by passing a vector of
sector names; the emissions of all listed sectors are summed:

```julia
emis = NEI2016MonthlyEmis(
    ["mrggrid_withbeis_withrwc", "emln_ptegu", "emln_ptnonipm", "emln_pt_oilgas",
        "emln_othpt", "emln_cmv_c3_12", "emln_cmv_c1c2_12"],
    domain)
# or equivalently
emis = NEI2016MonthlyEmis(["mrggrid_withbeis_withrwc"; NEI2016_ELEVATED_SECTORS], domain)
```

The six elevated sectors are also available on their own as [`NEI2016ElevatedEmis`](@ref)`(domain)`,
which can be coupled as a second emission system next to the surface one. A single system holding
all sectors is cheaper: sectors are summed at load time within each vertical profile, so every
species has one interpolator per profile (at most five) rather than one per sector and system.
At run time a species only reads the profiles that emit into the requested layer, and nothing
at all above its highest emitting layer (layer 11 for power plants), so the cost in the upper
layers of a 3-D model is small.

| sector                                              | contents                                                  | vertical profile |
|:--------------------------------------------------- |:--------------------------------------------------------- |:---------------- |
| `emln_ptegu`                                        | electricity generating units                              | `ptegu`          |
| `emln_ptnonipm`, `emln_ptnonipm_allinln`            | other industrial point sources                            | `ptnonipm`       |
| `emln_pt_oilgas`, `emln_pt_oilgas_allinln`          | oil and gas point sources, incl. offshore platforms       | `pt_oilgas`      |
| `emln_cmv_c3_12`, `emln_cmv_c1c2_12`                | commercial marine vessels (ocean-going; harbor and river) | `cmv`            |
| `emln_othpt`                                        | Canada and Mexico point sources                           | `surface`        |
| `emln_ptfire`, `emln_ptagfire`, `emln_ptfire_othna` | wild, agricultural and non-US fires                       | `surface`        |
| everything else                                     | surface sources                                           | `surface`        |

The EPA files are column totals. Elevated sectors are spread over model layers using the same
per-sector layer profiles that GEOS-Chem applies when it builds its NEI2016 3-D input files
(one representative profile per sector after Simpson et al. 2003, truncated at layer 11 of the
GEOS-FP grid). For example, only 2.8% of power-plant emissions go into layer 1 and 65% go into
layer 4 and above, while ships put 54% into layer 1 and the rest into layers 2 and 3. The default
sector-to-profile mapping is `EarthSciData.NEI2016_SECTOR_PROFILES`; pass `vertical_profiles` to
override it. Sectors that are not in the mapping go into the surface layer. If the model domain
has fewer layers than a profile, the fractions above the domain top are added to the top layer,
so the column total is kept.

Differences from GEOS-Chem's own use of these data: the low-level part of `ptnonipm` and
`pt_oilgas` is in the merged surface file and therefore emitted into layer 1, whereas GEOS-Chem
applies the sector profile to it as well (about 2.6% of `ptnonipm` and 0.7% of `pt_oilgas`
emissions are released lower here than in GEOS-Chem); and the mixing ratio conversion uses a
mean dry layer thickness rather than the simulated air mass.

The `_allinln` variants of `ptnonipm` and `pt_oilgas` include the part of those sectors that the
EPA platform also grids as 2-D surface files; with `mrggrid_withbeis_withrwc` use the base
variants to avoid counting that part twice.

## Equations

This is what its equation system looks like:

```@example nei2016
using EarthSciData, EarthSciMLBase
using ModelingToolkit, DynamicQuantities, DataFrames
using ModelingToolkit: t
using DynamicQuantities: dimension
using Dates

domain = DomainInfo(
    DateTime(2016, 5, 1), DateTime(2016, 5, 2);
    lonrange = deg2rad(-115):deg2rad(2.5):deg2rad(-68.75),
    latrange = deg2rad(25):deg2rad(2):deg2rad(53.7),
    levrange = 1:10,
    u_proto = zeros(Float32, 1, 1, 1, 1)
)

emis = NEI2016MonthlyEmis("mrggrid_withbeis_withrwc", domain)
```

## Elevated point sources (`NEI2016InlineEmis`)

The **2-D surface merge** (`mrggrid_withbeis_withrwc`) by construction excludes every
inline elevated point-source sector. The largest is
`ptegu` (EGU power plants), whose inline point sources inject a loader-measured
32.3 kg SO₂ s⁻¹ in March 2016 (~1.0 Tg yr⁻¹ annualized, roughly 40% of the
~2.5 Tg yr⁻¹ CONUS anthropogenic SO₂ budget) — the largest single share of the
anthropogenic sulfur missing from a surface-only run.

The monthly elevated sector files above ([`NEI2016ElevatedEmis`](@ref)) are one way to add these
emissions back; `NEI2016InlineEmis(sector, domaininfo)` is another, from hourly per-stack data.
Use one or the other for a given sector: coupling `NEI2016InlineEmis("ptegu", domain)` with
`NEI2016ElevatedEmis` (or with `emln_ptegu` in `NEI2016MonthlyEmis`) counts the power plants twice.

```julia
model = couple(
    domain,
    GEOSChemGasPhase(),
    NEI2016MonthlyEmis("mrggrid_withbeis_withrwc", domain),  # surface sectors
    NEI2016InlineEmis("ptegu", domain),                      # + elevated EGU
    GEOSFP("0.25x0.3125", domain),
)
```

Each stack's hourly `moles s⁻¹` emission is converted to a mass flux, scattered onto the
native 12US1 grid, and conservatively regridded — then injected into the model layer nearest
the cell's emission-weighted **Briggs** plume altitude (computed from the real stack
geometry), normalized by that layer's air mass.

### Data source and staging

The loader uses the public EQUATES CMAQ-ready inline files (AWS `cmas-equates` bucket). On
first use it Range-extracts only the members it needs — the sector's `stack_groups` file
(~230 KB, static geometry) and one `inln_mole` file per simulated day (~13 MB) — from the
multi-GB monthly tar, so **no full-archive download** occurs. On machines without internet
access, pre-stage the files first (run the constructor once on a machine that has network
access) or copy a populated `stage_dir`.

### Limitations (v1)

- **Proxy year.** EQUATES publishes model-ready inline files for **2017**, not 2016; the
  default `platform = :equates2017` uses 2017 as a documented proxy (EGU fleet year-to-year
  change is small). The TFLAG timestamps are remapped to the model year by month/day.
- **Static Briggs met.** Plume rise is precomputed at a reference wind/temperature
  (U = 5 m s⁻¹, Tₐ = 280 K), not the simulated meteorology. Online `Z_agl`-driven,
  state-dependent injection is the planned follow-up.
- **Mean-profile altitude→level.** Altitude is mapped to a model layer through a baked
  mean vertical grid, not the cell's live pressure profile.
- **Single effective plume per cell.** All stacks in a grid cell share one SO₂-weighted
  injection altitude (equal-weight fallback where a cell's stacks are all SO₂-free).
- **True hourly rates.** These are CEM-driven hourly emissions, so the days-in-month
  correction and the synthetic diurnal/day-of-week profiles applied to the surface
  inventory are deliberately **not** applied here (they would double-count).
