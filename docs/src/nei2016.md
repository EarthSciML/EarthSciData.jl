# 2016 US EPA National Emissions Inventory (NEI) data

We have a data loader for CMAQ-formatted monthly US National Emissions Inventory data for year 2016,[`NEI2016MonthlyEmis`](@ref).

## Download Configuration

Because there is an issue with the EPA's FTP server that we download the data from you may need to set the following environment variable before using it:

In Julia:

```julia
ENV["JULIA_NO_VERIFY_HOSTS"] = "gaftp.epa.gov"
```

or in a bash shell:

```bash
export JULIA_NO_VERIFY_HOSTS=gaftp.epa.gov
```

## Equations

This is what its equation system looks like:

```@example nei2016
using EarthSciData, EarthSciMLBase
using ModelingToolkit, DynamicQuantities, DataFrames
using ModelingToolkit: t
using DynamicQuantities: dimension
using Dates

domain = DomainInfo(
    DateTime(2016, 5, 1), DateTime(2016, 5, 2);
    lonrange = deg2rad(-115):deg2rad(2.5):deg2rad(-68.75),
    latrange = deg2rad(25):deg2rad(2):deg2rad(53.7),
    levrange = 1:10,
    u_proto = zeros(Float32, 1, 1, 1, 1)
)

emis = NEI2016MonthlyEmis("mrggrid_withbeis_withrwc", domain)
```

## Elevated point sources (`NEI2016InlineEmis`)

`NEI2016MonthlyEmis` reads only the **2-D surface merge** (`mrggrid_withbeis_withrwc`),
which by construction excludes every inline elevated point-source sector. The largest is
`ptegu` (EGU power plants), carrying roughly 2.2 of the ~2.5 Tg yr⁻¹ CONUS SO₂ budget — so
a surface-only run is missing most of the anthropogenic sulfur.

`NEI2016InlineEmis(sector, domaininfo)` adds an elevated sector back:

```julia
model = couple(
    domain,
    GEOSChemGasPhase(),
    NEI2016MonthlyEmis("mrggrid_withbeis_withrwc", domain),  # surface sectors
    NEI2016InlineEmis("ptegu", domain),                      # + elevated EGU
    GEOSFP("0.25x0.3125", domain),
)
```

Each stack's hourly `moles s⁻¹` emission is converted to a mass flux, scattered onto the
native 12US1 grid, and conservatively regridded — then injected into the model layer nearest
the cell's emission-weighted **Briggs** plume altitude (computed from the real stack
geometry), normalized by that layer's air mass.

### Data source and staging

The loader uses the public EQUATES CMAQ-ready inline files (AWS `cmas-equates` bucket). On
first use it Range-extracts only the members it needs — the sector's `stack_groups` file
(~230 KB, static geometry) and one `inln_mole` file per simulated day (~13 MB) — from the
multi-GB monthly tar, so **no full-archive download** occurs. On machines without internet
access, pre-stage the files first (run the constructor once on a machine that has network
access) or copy a populated `stage_dir`.

### Limitations (v1)

- **Proxy year.** EQUATES publishes model-ready inline files for **2017**, not 2016; the
  default `platform = :equates2017` uses 2017 as a documented proxy (EGU fleet year-to-year
  change is small). The TFLAG timestamps are remapped to the model year by month/day.
- **Static Briggs met.** Plume rise is precomputed at a reference wind/temperature
  (U = 5 m s⁻¹, Tₐ = 280 K), not the simulated meteorology. Online `Z_agl`-driven,
  state-dependent injection is the planned follow-up.
- **Mean-profile altitude→level.** Altitude is mapped to a model layer through a baked
  mean vertical grid, not the cell's live pressure profile.
- **Single effective plume per cell.** All stacks in a grid cell share one SO₂-weighted
  injection altitude (equal-weight fallback where a cell's stacks are all SO₂-free).
- **True hourly rates.** These are CEM-driven hourly emissions, so the days-in-month
  correction and the synthetic diurnal/day-of-week profiles applied to the surface
  inventory are deliberately **not** applied here (they would double-count).
